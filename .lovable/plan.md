

# Fix: Playwright Script Generation for Sidebar Navigation

## Problem Identified

After investigating the full pipeline (enriched steps, GPT-4o conversion, and automation results), the root cause is clear:

**Step 1 ("Click Master Data") succeeds** -- the runner clicks the sidebar menu item.
**Step 2 ("Click Curriculum") fails** -- the submenu item is not found.

This happens because:

1. **No wait between parent click and submenu click.** After clicking "Master Data", the sidebar submenu animates/expands. The runner immediately tries to find "text=Curriculum" before the submenu is visible.
2. **GPT-4o discards enriched step context.** The enriched steps contain valuable `location` ("left sidebar submenu under Master Data") and `notes` ("Expands the Master Data submenu"), but GPT-4o generates flat `selector_hints` with `wait_for: null`.
3. **No scoping of selectors.** "text=Curriculum" may match a page header or breadcrumb, not the sidebar link. The script should scope to the sidebar container.

## Evidence from the Database

The AI script generated by GPT-4o for TC-009 (Curriculum page loads):
```text
Step 1: click -> selector_hints: ["text=Master Data"]    -> wait_for: null  (PROBLEM)
Step 2: click -> selector_hints: ["text=Curriculum"]      -> wait_for: null  (FAILS HERE)
```

The enriched steps from Gemini Vision correctly say:
```text
Step 1: click "Master Data" in left sidebar, notes: "Expands the Master Data submenu"
Step 2: click "Curriculum" in "left sidebar submenu under Master Data"
```

The enriched data has the right info, but GPT-4o ignores it during conversion.

## Solution: Rewrite the GPT-4o Prompt

The fix is in `supabase/functions/prepare-automation/index.ts`. The prompt must be restructured to:

### Change 1: Force wait_for on menu expansion steps

Add explicit rules to the prompt telling GPT-4o:
- After any sidebar/menu click that "expands" a submenu, ALWAYS add `wait_for: "submenu visible"` or `wait_for: "navigation complete"`
- Never set `wait_for: null` on menu navigation steps

### Change 2: Preserve enriched step metadata

When enriched steps exist, pass them with a stronger instruction:
- "DO NOT reinterpret enriched steps. Convert them 1:1 into playwright_steps format."
- Map `location` to `fallback_strategy`
- Map `notes` to `wait_for` when they mention expansion/loading

### Change 3: Add scoped selector hints for submenus

When a step's `location` says "submenu under X", generate scoped selectors:
- Instead of just `text=Curriculum`, generate `role=navigation >> text=Curriculum` or `[data-sidebar] >> text=Curriculum`
- Add the unscoped selector as a fallback

### Change 4: Add a mandatory post-login navigation wait

Insert a rule: "After login, ALWAYS add a wait step for the dashboard/main page to fully load before any sidebar navigation."

## File Changes

### `supabase/functions/prepare-automation/index.ts`

Rewrite the `aiPrompt` section (lines 190-242) with these specific changes:

**A) Enhanced enriched steps instruction block (line 190-192):**
Replace the current `enrichedNote` with a much stronger directive that tells GPT-4o to convert enriched steps 1:1 without reinterpretation, preserving wait conditions from notes and scoping selectors from location data.

**B) New prompt rules (inside the main prompt, lines 194-242):**
Add three new critical rules:

1. **SIDEBAR/MENU NAVIGATION RULE**: "When clicking a parent menu item that expands a submenu, ALWAYS set wait_for to 'submenu expands and child items become visible'. Then for the submenu click, scope the selector: use the pattern 'nav >> text=ItemName' or add a waitForSelector-style hint."

2. **ENRICHED STEPS DIRECT MAPPING RULE**: "When enriched_steps exist, map them directly: enriched `action` becomes `action_type`, enriched `selector_hint` becomes the first entry in `selector_hints[]`, enriched `notes` containing 'expands' or 'loads' becomes `wait_for`, enriched `location` becomes `fallback_strategy`."

3. **POST-LOGIN WAIT RULE**: "After login steps complete, ALWAYS insert a wait step: `{action_type: 'wait', wait_for: 'page fully loaded, sidebar navigation visible'}`."

**C) Add an explicit pre-processing step (new code after line 183):**
Before sending to GPT-4o, if enriched steps exist, pre-transform them into the playwright format directly in code (without relying on GPT-4o). Use GPT-4o only as a fallback for test cases without enriched steps.

This is the most impactful change: instead of asking GPT-4o to interpret enriched steps, we programmatically convert them:

```text
For each enriched step:
  - action "click" with notes containing "expand" -> action_type: "click", wait_for: "submenu visible"
  - action "click" with location containing "submenu" -> selector_hints: ["nav >> text=Target", "text=Target"]
  - action "fill" -> action_type: "fill", input_value from step
  - action "assert" -> action_type: "assert", assertion from notes
  - action "wait" -> action_type: "wait", wait_for from notes
```

This bypasses GPT-4o entirely for enriched test cases, eliminating the translation loss.

## Expected Outcome

For the "Curriculum Page Load and Navigation" scenario, the generated Playwright instructions will become:

```text
Step 1: click ["text=Master Data", "role=menuitem >> text=Master Data"]
        wait_for: "Submenu expands and child items become visible"
Step 2: click ["nav >> text=Curriculum", "text=Curriculum"]  
        wait_for: "Curriculum page loads"
Step 3: assert ["text=Curriculum"] -- page header visible
...
```

The runner will then:
1. Click "Master Data" and WAIT for the submenu to expand
2. Find "Curriculum" scoped to the navigation area (avoiding false matches with page headers)
3. Wait for the page to load before asserting content
