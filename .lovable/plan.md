
# Filter Out Automation-Generated Failures from QA Dashboard

## Problem
The QA Tester dashboard currently displays all failed test results, including those generated by automated Playwright runs. As shown in your screenshot, these "Unknown Test" entries with errors like "Failed at: click - text=Curriculum" are automation failures that should not appear here. Per the project's isolation policy, automation failures belong exclusively in the Automation Bugs view (`/qa/automation/bugs`).

## Solution
Filter out automation-originated test results from the QA dashboard data query so only manually-executed failures appear.

## Technical Approach

### 1. Modify the data loading query in `QADashboard.tsx` (line 75-79)

Currently, the dashboard fetches **all** `test_results` from the last 30 days without filtering. Automation results are linked to `test_results` via the `automation_results.test_result_id` foreign key.

**Approach**: After fetching `test_results`, also fetch the set of `test_result_id`s from `automation_results`, then exclude those from the dashboard data before setting state.

Specifically:
- Query `automation_results` for all `test_result_id` values (non-null)
- Create a Set of those IDs
- Filter `allResultsData` to exclude any result whose ID is in that Set
- This filtered list feeds into `failedTests`, `allResults`, the "Failed Tests" stat card count, and the "Pass Rate" calculation

### 2. Files to modify
- **`src/pages/qa/QADashboard.tsx`** -- Add the automation exclusion filter inside `loadDashboardData`

### 3. What changes
- The "Failed Tests Need Re-testing" card will no longer show automation-generated failures
- The "Failed Tests" count in the stats cards will only reflect manual test failures
- The "Pass Rate" percentage will only consider manual test results
- No changes to the Admin or Developer dashboards (they have their own data loading)
- No changes to the `FailedTestsReminder` component itself -- it simply receives the already-filtered data
